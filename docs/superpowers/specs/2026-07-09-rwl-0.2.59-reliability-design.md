# rwl-install-wizard — 0.2.59 reliability fixes (design)

**Date:** 2026-07-09
**Status:** approved (design), pending spec review → writing-plans
**Scope:** `rwl-install-wizard` plugin only. Edits land in
`data/knob-catalog.yaml` + `data/` files; `skills/rwl-install/SKILL.md` only
for genuine interview/generate behavior; `lib/catalog-lint.sh` and
`tests/test-airgap-registry.sh` for the guard/oracle layers. Re-run
`lib/catalog-lint.sh` (must exit 0) after every edit.

## Problem

A STOXX POC ran the wizard and got a set of overlays
(`values-cluster/posture/storage/registry.yaml`) that are structurally valid
YAML but **fail `helm template` against chart 0.2.59** and encode several
semantic gaps. Six findings plus a cross-cutting META item. The reference
end-state is the operator's hand-written `values-fixes.yaml` +
`PREREQUISITES.md`; the deliverable is: *for the same interview answers, the
plugin would have produced install-ready output equivalent to (corrected
overlays + PREREQUISITES.md)* — resolving [1][4][5][6] automatically,
surfacing [2] as a prerequisite, and eliminating [3] by refusing to guess.

## Non-negotiable decisions (locked in brainstorming)

- **Render gate is command-only.** The plugin NEVER runs `helm` at generate
  time. Findings [1]/[6] are prevented by correct-by-construction emits and
  static catalog invariants — not by an at-generate render.
- **Unresolved axes: hard re-prompt.** The interview never finishes an axis
  with a guessed value. No `*.DRAFT.yaml`, no `UNRESOLVED.md`. Axes STOXX
  guessed (registry host, ingress class, cluster ingress-shape) become
  required questions with no guess-fallback. Every emitted file stays
  install-ready by construction.
- **[4] snippet support is its own question** with a posture-derived default
  (NOT a silent auto-derivation), because snippet support is a property of
  the ingress-controller deployment, not the platform posture — the operator
  must be able to say "hardened posture, but my controller allows snippets."

## Architecture — correctness without running helm

Three non-helm layers, in precedence order:

1. **Correct-by-construction emits (primary, `knob-catalog.yaml`).** Every
   option on every axis emits a chart-valid state. No option "emits nothing"
   in a way that leaves a hard-fail latent (root cause of [1]).
2. **Static invariant checks (`lib/catalog-lint.sh`).** Assertions over the
   catalog itself; exit non-zero on violation. Runs at lint time
   (maintainer + CI). Catches a maintainer reintroducing a latent hard-fail.
3. **Maintainer render oracle (`tests/test-airgap-registry.sh`).** The plugin
   test suite has the chart, so it renders generated fixtures through
   `helm template` against 0.2.59 and asserts exit 0. This is the only place
   a real render happens — offline from the operator. **Invoked with an
   explicit `helm template … -f a -f b` argv array, never a space-joined
   string variable** (under zsh an unquoted `"$VAR"` holding `-f a -f b`
   collapses to a single argument and silently mis-invokes).

The operator also receives the render-gate **command** in `PREREQUISITES.md`
§6 as belt-and-suspenders, but the plugin's guarantee does not depend on the
operator running it.

## Findings → changes

Each change names the file(s) it touches. Unless noted, changes are catalog
data (`data/knob-catalog.yaml`) or a `data/` companion file.

### [1] llm-endpoint must always emit a valid llmGateway state
- **Chart fact:** `templates/llm-gateway/configmap.yaml:18-19` — `fail`s
  unless `llmGateway.deploy=false` OR `llmGateway.models[]` non-empty OR
  `llmGateway.configMapName` set.
- **Change:** replace the option that emitted nothing
  (`default-bootstrap`). The axis default option becomes **"configure
  later"** → emits `llmGateway.deploy: false`. Every other option that sets
  `deploy: true` MUST emit `models[]` (non-empty) XOR `configMapName`.
- **Invariant (lint, [B2]):** `llmGateway.deploy: true ⇒
  (models[] non-empty) XOR (configMapName set)`.

### [2] cert-manager prerequisite (runwhenCA.deploy)
- **Chart fact:** `runwhenCA.deploy=true` (chart default) renders
  `cert-manager.io/v1` Issuer + Certificate.
- **Change:** new interview question *"Is cert-manager installed in the
  cluster?"* (SKILL.md interview + a catalog axis/option pair).
  - **no** → emits `runwhenCA.deploy: false`.
  - **yes** → keep chart default (`true`); add cert-manager to
    `PREREQUISITES.md` §1 as a hard cluster dependency with verify commands.

### [3] no guesses — hard re-prompt (three required questions)
- **registry-routing:** when image mirroring is enabled, the registry host is
  **required**; the interview blocks until provided. Never emits a placeholder
  host.
- **cluster-shape:** new first-class question **ingress vs Gateway API**. If
  Gateway API is chosen, the plugin does NOT emit any `ingress.*` keys (STOXX
  wrongly emitted `ingress.className`).
- **ingress className:** required (no `"nginx"` default) whenever the ingress
  path is chosen.

### [4] snippet-annotations (own question, posture-derived default)
- **Chart fact:** `templates/runner-metric-proxy/ingress.yaml` renders only
  when `or .Values.ingress.allowSnippetAnnotations $renderWithoutSnippet`.
  Hardened ingress-nginx rejects `allowSnippetAnnotations: true` (CVE-2021-25742).
- **Change:** new question *"Does your ingress controller allow snippet
  annotations?"* — **default NO when security-posture is hardened**,
  pre-filled from the posture answer, overridable.
  - **no** → emits `ingress.allowSnippetAnnotations: false` AND
    `runnerMetricProxy.cnValidation.enabled: false` +
    `runnerMetricProxy.ingress.renderWithoutSnippet: true` (else the
    runner-metric-proxy Ingress is silently dropped).
  - **yes** → no snippet-suppression emit.
- Only relevant when the ingress path (not Gateway API) is chosen and
  `runnerMetricProxy` is enabled.

### [5] posture split — first-party vs stateful subchart
- **Chart fact:** global `containerSecurityContext.readOnlyRootFilesystem:
  true` breaks Spilo/Patroni (needs writable rootfs); uid override does NOT
  reach the subchart but `readOnly` DOES.
- **Change:** when hardened posture is chosen AND bundled postgres is in use,
  also emit `postgresql.spilo.containerSecurityContext` that **replaces** the
  global context — re-asserting the other hardening
  (`allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`) and relaxing
  only `readOnlyRootFilesystem: false`. Modeled as a coupled emit fragment on
  the posture axis, gated by "bundled postgres in use?".

### [6] explicit postgresql.kind: spilo
- **Chart fact:** `values.yaml:623` `kind: "spilo"` is an implicit default
  the wizard relied on.
- **Change:** any option emitting `postgresql.spilo.*` also emits
  `postgresql.kind: spilo` (mirrors the already-correct `objectStorage.kind`
  pattern).
- **Invariant (lint, [B2]):** any emit containing `postgresql.spilo.*` must
  also contain `postgresql.kind: spilo`.

## META — PREREQUISITES.md + gates

### PREREQUISITES.md (per-run, parameterized)
Generalize the STOXX file into a template rendered by the GENERATE step in
`SKILL.md`. Emitted every run. Sections included **conditionally** on the
interview answers:
- **Header:** chart, chartCompat, generatedAt, apply-order.
- **§1 Cluster dependencies:** cert-manager (only if `runwhenCA.deploy:
  true`), Ingress controller/class (only if ingress path), snippet-annotations
  note (only if relevant).
- **§2 Registry & images:** only if mirroring is enabled; lists the required
  registry host and mirrored paths (from answers, never guessed).
- **§3 Pre-created secrets:** derived from chosen axes (corp CA bundle,
  wildcard TLS, seaweedfs identities, registry pull secret).
- **§4 StorageClass:** the chosen storage class.
- **§5 LLM endpoint:** only if `llmGateway.deploy: false` ("configure later").
- **§6 Pre-flight render gate:** copy-paste `helm template … -f <each file>`
  (explicit argv) + `kubectl apply --dry-run=client`.

Nothing in PREREQUISITES.md is hardcoded to STOXX; every value comes from the
interview answers.

### catalog-lint.sh invariants
Add the [1] and [6] static checks above; exit non-zero on violation. Keep
existing lint behavior intact.

### test-airgap-registry.sh (render oracle)
Extend to render the new axis combinations against chart 0.2.59 and assert
exit 0:
- llm-endpoint = "configure later" (`deploy: false`).
- cluster-shape = ingress with className, and cluster-shape = Gateway API
  (asserts NO `ingress.*` emitted).
- security-posture = hardened + bundled postgres (asserts
  `postgresql.kind: spilo` and the spilo `containerSecurityContext` override
  present; asserts render exit 0).
- snippet-annotations = no (asserts `renderWithoutSnippet: true` +
  `cnValidation.enabled: false`, and the runner-metric-proxy Ingress renders).
All helm invocations use an explicit argv array.

## Testing

- **Guard:** `lib/catalog-lint.sh` exits 0 on the fixed catalog.
- **Oracle:** `tests/run-all.sh` green — the render oracle covers the STOXX
  combination (llm configure-later + hardened + spilo + ingress-with-class +
  snippets-off), which previously hard-failed on [1].
- **Non-vacuity:** a lint-level negative test asserts the *pre-fix* catalog
  shape (an option that emits `spilo.*` without `kind`, or a `deploy: true`
  option without models/configMapName) is REJECTED by the new invariants — so
  the guard is not inert.
- **Provenance headers:** each generated overlay keeps its per-file provenance
  header; extend it with a "resolved" marker confirming no guessed values (all
  axes answered).

## What the plugin already got right (keep / generalize)

Structurally valid YAML; correct chartCompat pinning; `objectStorage.kind`
pinned; trust-bundle wiring; wildcard cert delegated to `existingSecret`;
consistent registry rewriting with a pinned-tags warning; per-file provenance
headers (now extended with the resolved marker).

## Out of scope

- The neo4j-external agentfarm/usearch chart bug (documented known-issue;
  belongs in rwlight-helm, not this plugin).
- Any change to `skills/` beyond the new interview questions and the
  PREREQUISITES.md generation step.
- Running helm at operator generate time (explicitly rejected).
