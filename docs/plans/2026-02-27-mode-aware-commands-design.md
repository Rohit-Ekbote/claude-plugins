# rwenv: Mode-Aware Command Construction & Auto-Approval

## Problems

### 1. Permission Prompts for Compound Commands

The auto-approval hook (`transform-commands.sh`) extracts the base command via `awk '{print $1}'`. For compound commands constructed by agents (e.g., `PASSWORD=$(docker exec ... | base64 -d) && docker exec ... sh -c "..."`), the first word is `PASSWORD=$(docker` — not `docker` — so the auto-approval path is never reached. Users get prompted for every agent-constructed command.

### 2. Local Mode Ignored by Agents

Only the hook checks `useDevContainer` and conditionally omits `docker exec`. But agents construct commands directly — `build_kubectl_cmd()`, `build_psql_cmd()`, etc. in `rwenv-utils.sh` always hardcode `docker exec`. Agent docs (`k8s-ops.md`, `db-ops.md`) say "MUST be executed through the dev container" with no mention of local mode.

## Solution

Three architectural changes:

1. **Env file runtime config** — `/rwenv-set` reads `envs.json` once, writes a flat `.claude/rwenv-env` file. Hooks and agents source this file instead of parsing JSON.
2. **Agents construct mode-aware commands** — Agent docs guide Claude to check `RWENV_MODE` and build commands accordingly. No hook transformation.
3. **Validation-only hook** — Hook validates commands have correct flags/wrapping, enforces safety, and auto-approves. Does not transform.

## Design

### Configuration Schema

**`envs.json` — source of truth (read only by skills):**

```json
{
  "version": "1.0",
  "useDevContainer": true,
  "devContainer": "alpine-dev-container-zsh-rdebug",
  "rwenvs": {
    "rdebug": {
      "type": "gke",
      "description": "Debug cluster",
      "container": {
        "kubeconfigPath": "/home/rundev/.kube/rdebug-61-config",
        "kubernetesContext": "rdebug-61"
      },
      "local": {
        "kubeconfigPath": "~/.kube/config",
        "kubernetesContext": "rdebug-61"
      },
      "readOnly": false,
      "gcpProject": "my-project",
      "fluxGitRepo": "https://github.com/..."
    }
  }
}
```

Key change: `kubeconfigPath` and `kubernetesContext` move into `container` and `local` sub-objects. Same key names, different values per mode. The `local` sub-object is `null` until first local mode activation triggers auto-detection.

No auto-migration. Users update `envs.json` manually.

### Runtime Env File

**`.claude/rwenv-env` — derived config for hooks and agents:**

```bash
# Generated by /rwenv-set and /rwenv-local-mode. Do not edit manually.
RWENV_NAME=rdebug
RWENV_TYPE=gke
RWENV_MODE=container
RWENV_KUBECONFIG=/home/rundev/.kube/rdebug-61-config
RWENV_CONTEXT=rdebug-61
RWENV_READ_ONLY=false
RWENV_GCP_PROJECT=my-project
RWENV_DEV_CONTAINER=alpine-dev-container-zsh-rdebug
RWENV_FLUX_REPO=/Users/rohitekbote/.claude/rwenv/flux-repos/rdebug
```

Rules:
- Plain `KEY=VALUE`, one per line, no `export` prefix
- Generated only by `/rwenv-set` and `/rwenv-local-mode`
- Auto-gitignored alongside `.claude/rwenv`
- If file missing, hooks block: "No rwenv configured. Run /rwenv-set."
- Replaces the existing `.claude/rwenv` plain text file

### Hook Architecture

**Single validation + auto-approval hook (`transform-commands.sh`):**

```
Source .claude/rwenv-env
  ↓
RWENV_NAME empty? → block: "No rwenv configured"
  ↓
Safety checks:
  - Read-only mode? Block write ops (kubectl apply/delete, helm install, etc.)
  - gcloud for k3s? Block
  - gcloud write? Always block
  - Dangerous docker ops against dev container? Block
  ↓
Validation (mode-specific):
  - container mode: kubectl/helm/flux must be inside docker exec $RWENV_DEV_CONTAINER
                    with --kubeconfig and --context flags
  - local mode: kubectl/helm/flux must have --kubeconfig and --context flags
  - Missing flags? Block with: "Missing --kubeconfig/--context. Source .claude/rwenv-env."
  ↓
Auto-approve: command passed validation and safety → permissionDecision: "allow"
```

No transformation. No separate container/local hook files. One hook validates and approves.

### Agent Updates

**All agent docs (`k8s-ops.md`, `db-ops.md`, `gcloud-ops.md`, `flux-ops.md`) updated:**

Prerequisites become:
1. Source `.claude/rwenv-env` from the working directory
2. Check `RWENV_MODE` to determine command pattern

Command patterns:

| Mode | kubectl example |
|------|----------------|
| `container` | `docker exec -i $RWENV_DEV_CONTAINER kubectl --kubeconfig=$RWENV_KUBECONFIG --context=$RWENV_CONTEXT get pods -n backend-services` |
| `local` | `kubectl --kubeconfig=$RWENV_KUBECONFIG --context=$RWENV_CONTEXT get pods -n backend-services` |

**db-ops specific changes:**

| Mode | Password fetch | Port-forward | Query |
|------|---------------|--------------|-------|
| `container` | `docker exec $RWENV_DEV_CONTAINER kubectl ... get secret ...` | `docker exec $RWENV_DEV_CONTAINER kubectl ... port-forward ...` | `docker exec $RWENV_DEV_CONTAINER sh -c "PGPASSWORD=... psql ..."` |
| `local` | `kubectl ... get secret ... \| base64 -d` | `kubectl ... port-forward ...` | `PGPASSWORD=... psql -h localhost ...` |

### Library Updates (`rwenv-utils.sh`)

**Mode-aware functions — read env vars instead of parsing JSON:**

- `build_kubectl_cmd()`, `build_helm_cmd()`, `build_flux_cmd()`, `build_psql_cmd()` check `RWENV_MODE` env var
- `get_kubeconfig_path()`, `get_kubernetes_context()` read from env vars
- Remove `build_docker_exec_prefix()` as a standalone function (inlined into mode check)
- Keep `load_envs()` and JSON-parsing functions for use by skills only

### Skills Updates

**`/rwenv-set`:**
1. Reads `envs.json`, validates rwenv name
2. Checks `useDevContainer` to determine mode
3. Reads kubeconfig/context from appropriate sub-object (`container` or `local`)
4. If local mode and `local` sub-object is `null` → trigger auto-detection:
   - Scan `~/.kube/config`, `~/.kube/*.yaml`, `KUBECONFIG` env var
   - Find contexts matching the rwenv's container context name
   - Present matches to user for confirmation
   - Persist chosen values into `local` sub-object in `envs.json`
5. Writes `.claude/rwenv-env` with all resolved env vars
6. Auto-gitignores `.claude/rwenv-env`

**`/rwenv-local-mode`:**
1. Reads `envs.json`, flips `useDevContainer`
2. If switching to local: validates `local` sub-object exists for current rwenv, triggers auto-detection if not
3. Validates local tools available (warns if kubectl/psql not found)
4. Persists `useDevContainer` to `envs.json`
5. Regenerates `.claude/rwenv-env` with new mode's values

**`/rwenv-cur`:**
- Sources `.claude/rwenv-env` and displays values. No JSON parsing.

**`/rwenv-list`:**
- Still reads `envs.json` directly (listing skill, not on hot path).

**`/rwenv-add`:**
- Creates rwenv entries in `envs.json` with both `container` and `local` sub-objects (`local` can be `null` initially).

**`scripts/pg_query.sh`:**
- Sources `.claude/rwenv-env` and constructs commands based on `RWENV_MODE`.

## Summary

| Component | Before | After |
|-----------|--------|-------|
| Config source of truth | `envs.json` (read everywhere) | `envs.json` (read only by skills) |
| Runtime config | JSON parsing on every command | `.claude/rwenv-env` flat file, sourced |
| envs.json schema | Flat `kubeconfigPath`/`kubernetesContext` | `container`/`local` sub-objects |
| Hook role | Transform + safety + auto-approve | Validate + safety + auto-approve |
| Command construction | Hook transforms bare commands | Agents construct mode-aware commands |
| Agent prerequisites | Read `.claude/rwenv` then parse envs.json | Source `.claude/rwenv-env` |
| Local mode | Partially broken (agents ignore it) | Fully supported end-to-end |
| Auto-approval | Misses compound commands | Validates whole command, approves if safe |
